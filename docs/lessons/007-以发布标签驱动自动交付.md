# 以发布标签驱动自动交付

- 发布 tag 是正式交付入口，源码版本是版本号唯一来源。严格比对 `releases/vX.Y.Z`、annotated 类型、提交与发布说明，尽早拒绝错误发布输入。
- 工作流应复用本地构建和打包脚本，避免 CI 与手动发布各维护一套规则。固定工具链版本和 checkout 提交，使依赖升级可审查。
- 二进制、源码、校验和与插件列表条目应由同一次构建生成。源码附件必须包含工作流，便于追溯交付方式。
- 先上传草稿再公开能缩小失败影响；显式检查原生命令退出码，避免 PowerShell 错误语义造成误发布。
- 同 tag 串行并拒绝覆盖已有 Release，保护公开包的哈希与下载地址。失败恢复区分未创建、部分草稿、完整草稿和已公开状态。
- 验证发布链路时使用临时副本及临时 Git 仓库，保护真实 tag 和冻结 ZIP。CI 的模型/脚本检查不能代替真实宿主与插件管理器验证。
