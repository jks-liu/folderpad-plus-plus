# Windows 控件自动化的消息边界

## 问题
- 直接跨进程发送 `WM_NOTIFY` 不能可靠模拟控件通知。
- 同步向 ListView 发送鼠标按下消息，会进入拖动检测循环，测试程序等返回后才发鼠标松开，形成等待。
- 标签数量更新并不代表列表行已经完成刷新；原生目录选择窗口的控件也是异步初始化。

## 解决
- 使用控件真实的键盘/鼠标输入路径，让控件在宿主内部生成通知。
- 连续 PostMessage 按下和松开，再轮询最终激活的 buffer。
- 等待最终可观察的标签、列表行与 buffer 状态，不将中间状态误判为失败。
- 目录选择测试接受原生对话框当前目录并核对持久化；中文与嵌套目录的归属由独立样例覆盖。

测试通过 PID 隔离，只读取测试进程内存和操作其窗口，不影响用户已有编辑器。
